The structural claim can be retained after separating it from the incorrect evaluator; the low-cover sign remains unproved. See `U3-CORRECTION.md`.

**U2:** From `q_j=sum_i i_(j-1)(J_i)`, the relevant difference is `sum_i Delta_(j-2)(J_i)`. The report's generic sentence using `Delta_(j-1)` is a false implication, with an exact four-vertex marked forest counterexample in `EVIDENCE.json`. Its later `j=p`, `r=p-2` calculation uses the correct rank, so the explicitly conditional pointwise theorem is not invalidated by that sentence. At second-shell `s=3,p=6`, however, an `ell=2` block needs `d=3,r=4`, below generic `K(3)=5`; matching size four alone does not invoke the r25 theorem. The separately audited odd-order four-matching injection covers `i_5<=i_4` for this 11-vertex residual when the cover loss supplies four matching edges. This distinction repairs the application prose without silently enlarging the main conditional theorem. See `U2-CORRECTION.md`.

**F1:** The sample's reported `CT_x` column is the flat gap `(x+1)Q-E`. The actual CT_x gap is `(x+1)i_(x+1)(T)Q-i_x(T)E`; current-rank gap is `(p-1)Q-E`. In the 37 recorded eligible rows `p=x+2`, so flat equals current, but actual CT_x remains stronger since `i_(x+1)<i_x`. Both critiques repeated the incorrect equivalence. I independently recomputed the independence polynomial, `alpha`, `x`, original-leaf selector, and selected sum on all 37 recorded trees with a different tree DP, then combined the resulting `i_x,i_(x+1)` with the recorded `Q,E`. All 37 actual CT_x gaps are positive (minimum `123300`), as are all flat/current gaps (minimum `1001`); these agree row by row with the pinned controller diagnostic. The exact RETURN statement `E<=(x+1)Q` remains a valid bounded claim. It is still only a sample: zero proper selectors, no rows at `p>x+2`, no universal conclusion. See `F1-CORRECTION.md`.
