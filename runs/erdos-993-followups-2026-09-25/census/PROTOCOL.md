# Proposed byte-frozen forest census protocol (Phase A)

Status: **proposed for controller admission; no order-20 or order-24 production run has started.** The controller must record the exact source hashes before production. Any subsequent source correction requires a new version and a new admission record; old source and results remain intact.

## Scope and definitions

For a forest (G), (i_j(G)) counts independent vertex sets of size (j), with (i_j=0) outside the natural range. Let (Delta_j=i_{j+1}-i_j), and (x(G)=\min\{j:\Delta_j<0\}). The strict inequality is essential: a plateau is skipped. The empty graph is a class of order zero, with independence polynomial (1) and (x=0). Isolates are ordinary one-vertex tree components and may occur with arbitrary multiplicity up to the order cap.

The two targets are (1) (M(6)=\max\{|V(G)|:\Delta_6(G)<0\}), and (2) (x(G+K_1)\le x(G)+1) for **every** forest with (x(G)\le6). The formal r27 bound (Delta_k(G)<0\Rightarrow |V(G)|\le4k) makes orders 0–24 exhaustive for target 1. For target 2, the same bound applied to (x(G)\le6) confines the relevant forests to order at most 24. No inference from unimodality or from two consecutive negative differences replaces the literal first-descent scan.

The instrument computes (i_0,\ldots,i_8). For (j=0,\ldots,7), it tests 

\[
\Delta_j(G+K_1)=i_{j+1}(G)-i_{j-1}(G),\qquad i_{-1}(G)=0.
\]

For each class with (x(G)\le6), it finds the first negative right-hand side, including plateaus. A missing negative through (j=7) is a closure failure. The report tabulates all (x\to x(G+K_1)) transitions, failure counts, and one deterministic worst-margin witness per (x=0,\ldots,6).

## Exhaustive class generation

The implementation adapts `scratchpad/c1-sr-SR-EXX/sr_exx_census.py` from remote experiment `erdos-993-forest-degree-extension-dre-2026-09-24`. It changes the rooted cap from 10 to 12, small-component cap from 10 to 12, and the packed coefficient window from 7 to 9 digits. The original file is read-only and is not edited. The earlier 2026-09-02 order-20 frozen-byte protocol was consulted for the rule that source and serialization must be fixed before a production scan. This is a new census, with its own record schema and digest; it does not claim byte compatibility with the older tree/leaf stream.

Every rooted tree of size at most 12 is constructed as a multiset of rooted child trees whose sizes sum to one less than the parent size. The list stores **one entry per rooted isomorphism class**, even when two classes have identical include/exclude polynomials. The rooted code is `(`, then the bytewise-sorted child codes, then `)`.

Every free tree of order (n\le24) is generated by the centroid decomposition. A unicentroidal tree has a unique centroid; its rooted branches each have size at most (\lceil n/2\rceil-1). A bicentroidal tree has even order (2m) and is an unordered pair of rooted trees of size (m), joined at their roots. The cases are disjoint, and each isomorphism class has exactly one such decomposition. A free-tree polynomial counter stores the number of distinct tree classes giving that polynomial; equality of polynomials never deduplicates a tree class.

Every forest of order at most 24 either has all components of order at most 12, or has exactly one component larger than 12. The first family is generated as a nondecreasing-index multiset of **individual** small free-tree classes. The second combines one large tree polynomial with one small forest of complementary order at most 11. Its class weight is the product of the two polynomial multiplicities. These two families are disjoint and exhaustive. No full list of 146 million forest classes is serialized. Large-tree counters flush at 250,000 distinct polynomials, bounding live memory without changing class weights.

For a rooted tree, `out=product(child.out+child.in)` and `in=z*product(child.out)`. The unicentroidal tree uses `out+in`; a bicentroidal tree joined at roots uses `outA*outB+inA*outB+outA*inB`. Forest polynomials multiply over components. Each packed base-(2^{32}) digit is a coefficient. Every intermediate polynomial counts subsets of a graph on at most 24 vertices, so every coefficient is at most (2^{24}<2^{32}); multiplication and addition cannot carry across digits. A nine-digit mask discards only coefficients above degree eight, which cannot affect either target.

## Fixed controls and independent checks

The source asserts rooted-tree class counts through order 12, free-tree class counts through order 24 (OEIS [A000081](https://oeis.org/A000081/b000081.txt), [A000055](https://oeis.org/A000055/b000055.txt)), and forest class counts through order 24 ([A005195](https://oeis.org/A005195/b005195.txt)). These count tables are controls, not a substitute for the generation argument. A separate Euler transform of the free-tree counts must reproduce every forest count. In particular the order-24 controls are 39,299,897 trees and 90,328,674 forests; cumulative forests including the empty graph are 146,271,594.

The baseline order-20 run must reproduce the r27 (M_0,\ldots,M_5=(0,4,8,11,15,18)) controls. The independent `independent_small.py` comparator enumerates labelled trees from Prüfer words, quotients by canonical AHU codes, forms forest multisets, and obtains each independence polynomial by direct vertex-subset counting. It checks **all** report strata for orders 0–7. The separate `fixtures.py` checks the empty graph, plateaus, a synthetic positive closure-failure decision, the exact (K_1) difference identity, and independent path checks (i_6(P_{22})=12376), (i_7(P_{22})=11440), (\Delta_6(P_{23})=884). The synthetic failure fixture checks decision logic; it is not asserted to be a graph.

For each (j=0,\ldots,6), the report selects a maximum-order negative-\(\Delta_j\) polynomial, breaking equal-order ties by the least packed integer. It reconstructs an actual centroid-coded component multiset for that polynomial and recomputes all nine coefficients using a separate vertex-deletion recurrence. It does the same for the worst observed closure margin in each (x) stratum. `U:` denotes a unique-centroid rooted AHU code, `B:` an unordered pair of rooted AHU codes separated by `|`; the forest witness is a list of component codes. This is a replayable graph certificate, with isolates represented as `U:()`.

## Frozen bytes and execution

The proposed source bundle is `forest24.py`, `independent_small.py`, `fixtures.py`, and this protocol. The controller's admission record pins their SHA-256 hashes. The mathematical report is one UTF-8 JSON object with keys recursively sorted, separators exactly comma and colon, decimal integer syntax, and one final LF. It contains no clock data or floating-point numbers. Per-order rows contain total class count, exact first-descent strata (`0` through `6`, `>6`), each negative-\(\Delta_j\) count (`j=0..6`), exact direct-closure transition counts, and closure-failure count. It also contains rooted/free/forest class counts, all (M_j) over the scanned range, extremal graph witnesses, worst closure witnesses, and total counts. The report SHA-256 is recorded in a separate `.execution.json` receipt, which also holds elapsed time and source hash. Only the report is expected to be byte-reproducible across runs.

Run from the followup project root after controller admission:

```sh
python3 -m py_compile census/forest24.py census/independent_small.py census/fixtures.py
python3 census/fixtures.py
python3 census/forest24.py --max-order 12 --out census/validation12.json
python3 census/independent_small.py census/validation12.json
python3 census/forest24.py --max-order 20 --out census/baseline20.json
python3 census/forest24.py --max-order 24 --out census/production24.json
```

The order-20 and order-24 commands are **Phase B only**. Run one foreground Python process at a time, on at most one CPU worker and with no toolchain installation or background jobs. Expected work is about 146 million weighted forest classes by order 24, with streaming compression; a conservative planning allowance is tens of minutes and under 4 GB RAM. The process makes no network writes. A failed assertion aborts the run and must be reported, with the failing source and output preserved rather than overwritten under the same admitted identity.
